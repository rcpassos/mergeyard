Explore the workflow

Choose what gets picked up.

Label an approved issue ready-for-agent. Mergeyard claims eligible work and prepares an isolated Git worktree for the run.

Your agents. Separate roles.

Choose Claude Code or Codex independently for the implementer and reviewer. The implementer writes the change; Mergeyard opens a draft PR.

A review that comes back around.

A separate agent reviews the PR. Blocking findings go back to the implementer for fixes and re-review, within a configured round limit.

Check the code before the handoff.

Review approval waits for CI. Mergeyard monitors checks and supports bounded CI repair before the PR is ready to merge.

You keep the merge decision.

Inspect the local dashboard, watch a live session, stop a run, or take over the implementer’s conversation. Merge the PR yourself when you’re satisfied.

Start on your machine

Put an issue on track.

One local Go process, your existing GitHub repositories, and the coding agents you already use.

Build it. Set it up. Start it.

Build from source with Go 1.24 or newer. The dashboard assets are included in the repository.

Have Git, GitHub CLI, tmux, and your chosen agents installed and authenticated. Setup checks prerequisites and helps configure your first repository and both agent roles.

Once running, open http://127.0.0.1:7331 for the dashboard. Label an approved issue ready-for-agent to queue it.

Full setup guide
Build & run
git clone https://github.com/rcpassos/mergeyard.git
cd mergeyard
go build -o bin/mergeyard ./cmd/mergeyard

gh auth login
./bin/mergeyard init
./bin/mergeyard doctor
./bin/mergeyard start

Mergeyard runs agents with your local permissions. The default Claude configuration uses bypassPermissions for unattended work. Use trusted repositories and issues; review the permission settings before starting.
